## 슬로우 쿼리 


## 1. 슬로우 쿼리 분석을 하는 이유

- **병목 구간 발견**  
    느린 쿼리가 전체 시스템 응답 지연, CPU 과부하, 트래픽 처리 한계의 주원인일 수 있음
- **시스템 성능 저하 원인 규명**  
    무분별한 풀 테이블 스캔, 인덱스 누락, 비효율적 조인 등 쿼리 문제를 찾아냄
- **리소스 낭비 방지** 
    불필요하게 많은 CPU, I/O, 메모리 자원을 소모하는 쿼리를 찾아서 자원 효율 개선
- **사용자 경험 개선**  
    느린 쿼리를 개선해 API나 서비스 응답 시간을 줄임으로써 사용자 만족도 상승
    

---

## 2. 슬로우 쿼리 분석 시 주로 보는 정보

|정보 종류|용도 및 병목 확인 포인트|
|---|---|
|**실행 시간(Execution Time)**|쿼리가 얼마나 오래 걸리는지 → 성능 저하 직접 원인|
|**호출 빈도(Calls)**|자주 호출되는 느린 쿼리는 우선 튜닝 대상|
|**동시 실행 수 / 잠금 시간**|트랜잭션 잠금 병목이나 동시성 문제 감지|
|**스캔한 행 수(Rows Examined)**|인덱스 미사용, 풀 테이블 스캔 여부 판단|
|**반환된 행 수(Rows Sent)**|불필요하게 많은 데이터 반환 여부 확인|
|**쿼리 실행 계획(EXPLAIN)**|조인 방식, 인덱스 사용 여부, 쿼리 최적화 가능성 평가|
|**쿼리 텍스트**|비효율적 조건, 불필요한 함수 사용 등 코드 문제점 파악|

- 슬로우 쿼리 분석은 DB 병목을 찾아내는 **‘진단’ 단계**
    
- 주로 **실행 시간, 호출 빈도, 행 스캔 수**를 통해 쿼리의 ‘핫스팟’을 찾음
    
- 이후 튜닝, 인덱스 개선, 구조 변경 등의 **‘개선’ 작업**을 진행
    
- **지속적인 모니터링과 반복 개선**이 필수
